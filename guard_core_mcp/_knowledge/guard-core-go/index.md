# guard-core-go

The Go port of the guard-core security engine. Module `github.com/rennf93/guard-core-go`, directive `go 1.25.0`, dependencies on `dlclark/regexp2`, `redis/go-redis/v9` and `golang.org/x/text`.

## Install

```sh
go get github.com/rennf93/guard-core-go@v0.1.0
```

Tagged `v0.1.0` only (a pre-release snapshot). Version is carried entirely by the git tag; there is no version constant in the Go source.

## Setup

The engine pattern used by every Go adapter:

1. `cfg := guardcore.DefaultSecurityConfig()`
2. `engine, err := guardcore.NewEngine(cfg)`
3. `engine.Initialize()`
4. Hand the engine to an adapter constructor such as `nethttp.New(engine)`.

Direct detection entry point: `guardcore.Detect(content, ip, context)` returning a `DetectResult`. Route-level configuration registers through `engine.Routes.Register`, and adapters pick route ids off the request context with their `WithRouteID(ctx, id)` option.

## Conformance

`conformance/guard-core-spec-4.0.2/` vendors the frozen spec 4.0.2 fixture corpus: 163 cases across 11 suites (benign, boundaries, cmd_injection, context_matrix, encoding, inclusion_sensitive_recon, misc_injection, path_traversal, semantic, sqli, xss). `cases/index.json` pins `spec_version` 4.0.2 and reference `engine_commit` `886f8013`. `CORPUS.md` states the expected values were generated by the Python reference engine (enhanced 4.x detection path) and must never be hand-written.
